# מטלת פיתוח: עיבוד בקשת אישור רפואי באמצעות AI

## ההמלצה לתיק שסופק

המערכת ממליצה **APPROVE**.

דו״ח ה־CT מתאר נודול סולידי חלקית בגודל 18×15 מ״מ באונה הימנית העליונה, בסגמנט האחורי. לנודול שוליים משוננים, מרכיב סולידי של כ־12 מ״מ ו־Lung-RADS 4B. ב־PET-CT הנודול קולט FDG עם SUVmax של 4.2. הסיכום הרפואי ממליץ על דגימת רקמה. המסמכים מסבירים שהגישה הברונכוסקופית הרובוטית מתאימה למיקום הנגע ומפחיתה את סיכון חזה האוויר ביחס לביופסיה דרך דופן בית החזה, בפרט על רקע COPD. בדיקות המעבדה והקרישה תקינות, ותפקודי הריאה (FEV1 62%, DLCO 58% מהצפוי) אינם מצביעים על מניעה ברורה.

הנימוק שהמערכת הפיקה:

> הממצאים הקליניים תומכים בדגימת רקמה מנודול חשוד (18 x 15 mm, Lung-RADS 4B). הפרוצדורה המבוקשת מתאימה למיקום הנגע ולמצב הריאתי המתואר במסמכים (FEV1 62% מהצפוי, DLCO 58% מהצפוי), ובדיקות המעבדה ותפקודי הריאה אינן מצביעות על מניעה ברורה.

הפלט המלא נמצא ב־[results/supplied](results/supplied), בעברית ובאנגלית. הוא כולל את קובץ התוצאה, את העובדות המאומתות עם ציטוט ומספר עמוד, את הטקסט שנקרא, את כל תשובות המודל ואת קובץ ה־manifest.

## בדיקה על תיק נוסף

נוצר תיק הדגמה בדיוני ונפרד עבור Taylor Sample: נודול מוצק וחלק בגודל 6 מ״מ באונה הימנית האמצעית, יציב במשך 24 חודשים, Lung-RADS 2, עם המלצה למעקב הדמייתי שנתי וללא המלצה לדגימת רקמה. בדיקות המעבדה ותפקודי הריאה תקינות.

התוצאה היא **MANUAL_REVIEW**: הכללים ״נודול חשוד המצריך בירור״ ו־״הומלצה דגימת רקמה״ אינם נתמכים, ושני הכללים האחרים מתקיימים. קובצי המקור הבדיוניים נמצאים ב־[alternate_case](alternate_case), והפלט המלא ב־[results/alternate](results/alternate).

## איך הפתרון עובד

1. **קריאה.** הטקסט נקרא מכל מסמך PDF או DOCX, יחד עם מספר העמוד או הפסקה. לכל קובץ מחושבת טביעת hash. עמוד סרוק נכשל במפורש, אלא אם הופעל OCR מקומי.
2. **חילוץ.** כל שדה שמוגדר בפרופיל `lung_biopsy` נשלח למודל Gemma 4 המקומי (דרך Ollama) בקריאה נפרדת, עם סכמת JSON, טמפרטורה 0 ו־seed קבוע. המודל מחזיר ערך וציטוט מדויק, וכל ערך מועמד נשמר.
3. **אימות.** הקוד בודק שהציטוט מופיע במסמך ושמספר שייך למדד של השדה. כך ערך DLCO אינו יכול לעבור כ־FEV1, וסף כמו ״FEV1 >60%״ אינו נחשב תוצאה. הקוד גם מאחד תאריכים ומשווה שם, תאריך לידה ו־MRN בין המסמכים.
4. **החלטה.** קוד Python, ולא המודל, מפעיל את ארבעת כללי המטלה. APPROVE מתקבל רק כשכל כלל נתמך בראיה מאומתת, כל המסמכים קיימים, הזהות תואמת, פרטי הבקשה (פרוצדורה, קודי CPT ותאריך השירות) חולצו, ואין התוויית נגד או בעיה חוסמת. בכל מצב אחר מוחזר MANUAL_REVIEW, עם פירוט הכללים שלא התקיימו.

## הוראות הרצה

נדרשים Python 3.11 ומעלה ו־Ollama עם המודל Gemma 4:

    ollama pull gemma4
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -e .
    python -m approval case.json --language he --output-dir runs/medical

להרצת התיק הנוסף:

    python -m approval ai/alternate_case/case.json --language he --output-dir runs/alternate

`--language en` מפיק את ההסבר באנגלית. הוראות מלאות, דוגמאות נוספות ובדיקות נמצאות ב־[README](../README.md).

## בדיקות

- 64 בדיקות אוטומטיות מריצות את קוראי המסמכים, את האימות, את הכללים ואת רישום ההרצה. הן מחליפות רק את הקריאה למודל ורצות ב־GitHub Actions.
- הרצה חיה מול Gemma 4 המקומי של כל התרחישים, בעברית ובאנגלית: התיק שסופק, תיק רפואי בעברית, התיק הנוסף, וחמישה תרחישי חשבונית, כולל מסמך סרוק. כל התרחישים החזירו את התוצאה הצפויה, והתוצאות בעברית ובאנגלית היו זהות.

## מגבלות ושיפורים אפשריים

- **ציטוט מאומת אינו מוכיח פרשנות נכונה.** הבדיקה מוודאת שהטקסט קיים ושמספר קשור למדד שלו, אך אינה מוכיחה שהמודל הבין את המשפט. המודל עשוי להשמיט קביעה שלילית מפורשת; במקרה כזה התוצאה נשארת MANUAL_REVIEW ואינה הופכת לאישור.
- **סדר הערכים בתקציר.** כשנמצאו כמה ערכים מאומתים שונים לאותו שדה, למשל נודול שני ושפיר, התקציר מציג את הערך הראשון שמופיע במסמכים ומוסיף אזהרה. ההחלטה אינה תלויה בבחירה הזו.
- **היקף בדיקה מצומצם.** הפתרון נבדק על התיק שסופק, על תיק בדיוני אחד ועל דוגמאות בדיוניות. זו אינה הערכת דיוק.
- **מהירות.** כל שדה נשאל בנפרד בכל קטע טקסט, ולכן תיק רפואי נמשך שתיים עד שלוש דקות.
- **שיפורים עם זמן נוסף:** מערך הערכה רחב עם מסמכים חסרים, זהויות שאינן תואמות, סתירות וראיות שליליות; בדיקה סמנטית בין ערך לציטוט; וניסיון חוזר אוטומטי לקריאה שנכשלה.

זהו כלי הדגמה התומך בבדיקה אנושית, ואינו מערכת קלינית או ביטוחית מאומתת.
